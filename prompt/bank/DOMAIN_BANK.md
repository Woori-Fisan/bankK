# 은행 코어 시스템 (Bank Core System)

이 시스템은 중계 플랫폼(BaaS API Consumer)으로부터 인입되는 금융 트랜잭션을 처리하고, 실제 원장(Ledger) 데이터를 안전하게 영구 저장 및 관리하는 최종 금융 시스템입니다.

## 1. 타겟 사용자

- **중계 플랫폼 (BaaS Client)** : 은행이 제공하는 API를 호출하여 대리업체 화면에 데이터를 중계하는 내부 연동 서버

## 2. 주요 기능

- **원장 관리 (Ledger Management)** : 고객의 계좌 상태 관리(정상/정지/휴면), 실시간 잔액 관리를 수행한다.
- **금융 트랜잭션 처리** : 중계 플랫폼에서 전달된 요청을 데이터 무결성을 보장하며 처리한다.
- **코어뱅킹**: BaaS API기능 구현(이체/출금/조회/대출)
- **대출 심사 및 실행** : 중계 플랫폼에서 전달된 고객 정보를 바탕으로 신용점수 및 DSR을 계산하여 대출 한도와 금리를 산출하고 대출 원장을 생성한다.

## 3. BaaS API 기능
은행은 은행이 가지는 핵심 기능을 BaaS API로 열어서 접근 가능하도록 구현합니다.
BaaS는 Banking as a Service의 약자로, 은행의 고유 기능을 서비스로 제공함을 의미합니다.

## 4. 준수 사항

### 4.1. 보안 및 암호화 (Data Security)
중계 플랫폼과 달리 **고객의 민감 정보가 영구 저장되는 곳**이므로 최고 수준의 암호화를 강제한다.

- **디지털 봉투 해독 (RSA + AES)** : 중계 플랫폼으로부터 전달받은 암호문에서, 은행의 RSA 개인키(Private Key)를 사용해 '1회용 AES 세션 키'를 먼저 복호화합니다. 이후 획득한 AES 키로 페이로드 원본을 평문 해독하여 비즈니스 로직을 처리합니다.
- **영구 저장용 대칭키 암호화 (AES-256-GCM)** : 해독된 주민등록번호, 전체 계좌번호 등은 내부망 유출 방지를 위해 **은행 내부망 전용 AES 키**로 재암호화하여 DB에 저장합니다. (패턴 노출 위험이 있는 ECB 모드 금지)
- **블라인드 인덱스 (Blind Index)** : 암호화된 계좌번호로 DB 조회를 수행하기 위해, 별도의 해시 컬럼(`account_no_hash`, SHA-256)을 생성하여 WHERE 조건 검색에 활용합니다.

### 4.2. 데이터 무결성 (Transaction Integrity)
- **멱등성 보장 (Idempotency)** : 네트워크 지연이나 타임아웃으로 인해 플랫폼이 동일한 이체/출금 요청을 재시도하더라도, 중복 결제가 발생하지 않도록 고유 트랜잭션 ID를 통해 멱등성을 보장해야 한다.
- **동시성 제어 (Concurrency Control)** : 동일 계좌에 다수의 출금/이체 요청이 동시에 발생할 경우, 갱신 손실(Lost Update)로 인해 잔액이 마이너스가 되지 않도록 DB 락(Pessimistic Lock)을 반드시 적용한다.

### 4.3. 통신 및 검증
- **mTLS (서버 역할)** : 중계 플랫폼이 API를 호출할 때, 등록된 신뢰할 수 있는 플랫폼(클라이언트)의 인증서인지 상호 검증(mTLS)하여 인가된 접근만 허용한다.
- **JWS 서명 검증** : 금융 사고 발생 시 책임 소재를 명확히(부인 방지) 하기 위해, 플랫폼이 전달한 Request Body의 JWS 전자서명을 검증한 후 트랜잭션을 수행한다.

### 4.4. 로그 처리
- 모든 요청/응답에 대한 로그를 기입해야한다. 이때, 기록되는 로그는 모두 암호화된 정보이며, 요청의 종류와 상태(정상/에러), 요청 주체(대행기관 코드), 요청 대상(은행 코드)가 명시되어 있어야 한다.
