# 은행 대리업 중계 플랫폼 프론트엔드

은행 대리업을 중계하는 플랫폼의 프론트엔드 개발에서 지켜야할 사항을 명세합니다.

## 1. 기술 스택

| 구분 | 기술 | 비고 |
|------|------|------|
| 암호화 | Web Crypto API + jose | RSA/AES 처리 |

---

## 2. 업무 페이지 플로우

모든 업무 페이지는 Step 기반 UI로 구성합니다. 단계 간 이동은 페이지 전환이 아닌 컴포넌트 교체로 처리합니다.

- **이체**: 계좌 입력 → 수취인 확인 → 금액/비밀번호 입력 → 결과
- **출금**: 계좌 입력 → 잔액 확인 → 금액/비밀번호 입력 → 결과
- **대출**: 서류 제출 → 심사 대기(Polling) → 상품 선택 → 계약 서류 확인 → 실행 → 결과
- **조회**: 계좌 입력 → 잔액/거래내역 표시

**대출 심사 Polling**: 심사는 비동기 처리이므로 TanStack Query `refetchInterval`로 5초마다 상태 조회, `PENDING`이 아닌 상태가 오면 중단합니다.

---

## 3. 암호화 구현 규칙

- 로그인 비밀번호: 플랫폼 RSA 공개키로 암호화 (`useRsaEncrypt`)
- 금융 트랜잭션: 디지털 봉투 방식 (`useHybridEncrypt`)
    1. 1회용 AES-256 세션 키 로컬 생성
    2. 민감 페이로드를 AES 키로 암호화
    3. AES 키와 계좌 비밀번호를 은행 RSA 공개키로 암호화
- 은행 RSA 공개키는 로그인 시 1회 수신 후 Zustand를 통해 `bankKeyStore`에 캐싱, 거래마다 재요청 금지
- Key ID를 통해서 키 교체 시점 이전의 요청에 대해서 실행을 보장(BaaS 요청에 대해 Key ID를 명시한다.)
---

## 4. 핀패드 모달

계좌 비밀번호는 반드시 `PinPadModal`을 통해 입력합니다. 일반 input 직접 입력 금지.

- 숫자 배열은 렌더링마다 랜덤 셔플
- 입력값은 컴포넌트 내부 state에만 존재
- 입력 완료 시 즉시 암호화 후 암호문만 콜백으로 전달

### 4.1. 멀티 버튼 하이라이트

실제로 누른 버튼 외에 무작위로 선택된 다른 버튼들도 동시에 눌린 것처럼 시각적으로 반응합니다. 화면 녹화나 어깨너머 관찰로 입력 번호를 유추하기 어렵게 만드는 보안 연출입니다.

- 버튼 클릭 시 실제 입력 버튼 1개 + 랜덤 선택된 2~3개 버튼이 동시에 `active` 상태로 표시됩니다.
- `active` 상태는 100~150ms 후 일괄 해제합니다.
- 실제 입력값 처리는 클릭 이벤트 발생 즉시 수행하며, 시각 연출과 독립적으로 동작합니다.
- 랜덤 버튼 선택 시 실제 입력 버튼은 반드시 제외합니다. (동일 버튼이 두 번 하이라이트되어 역추적에 힌트를 주는 것을 방지)
