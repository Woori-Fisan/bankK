# 은행 대리업 중계 모니터링

중계 플랫폼이 은행 대리업의 통신을 위임받음에 따라 발생하는 장애 추적, 시스템 감시, 그리고 금융 사고 발생 시 책임 소재 자료를 수집합니다.

## 1. 타겟 사용자
- **플랫폼 시스템/운영 관리자**: 인프라 장애 대응, API 지연율 확인 및 Trace 기반의 고객 거래 실패 원인 조사.

## 2. 주요 기능

### 2.1. 메트릭 시각화 (Metrics)
- **수집**: AWS CloudWatch(기본 인프라) + Prometheus(WAS 커스텀 지표/TPS 등).
- **시각화**: Grafana 임베딩을 활용하여 단일 대시보드로 통합하고 임계치 초과 시 즉각 알람 발송.

### 2.2. 로그 파이프라인 (Logs & Tracing)
- **비동기 수집**: `Fluent Bit` ➔ `AWS Kinesis Firehose` 흐름으로 트래픽 유실 및 성능 저하 방지.
- **분산 추적**: 모든 API 요청에 `Trace-ID`를 발급하여 대행기관 단말기부터 은행 코어까지의 전체 흐름을 하나로 묶어 식별.
- **이원화 저장**: OpenSearch(단기 보관/실시간 검색용)와 S3(장기 보관/감사용)로 분기.

## 3. 필수 준수 사항

### 3.1. 법적 증거 보존
- 장기 보관용 S3 버킷에는 객체 잠금(Object Lock)을 적용하여, 관리자를 포함한 누구도 로그를 수정/삭제할 수 없도록 원천 차단합니다.

### 3.2. 성능 영향 최소화 (비동기)
- 시스템 메인 스레드를 차단하지 않도록, 모든 로깅과 모니터링 데이터 전송은 완전 비동기로 처리합니다.

### 3.3. 접근 통제 및 시각화 규칙
- **보안**: 모니터링 대시보드(Grafana Iframe)는 JWT 인증된 사용자만 접근할 수 있도록 보호합니다.
- **색상 규약**: 인지 지연을 막기 위해 상태 색상을 통일합니다 (Green: 정상, Orange: 경고/지연, Red: 위험/장애).
